# Backup, Restore and CSV Export Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On More → Your data, Back up and Export CSV share a file, and Restore loads a backup file in place of the current data.

**Architecture:**
- **Pure and tested:** CSV building (`src/domain/csv.ts`) and the restore checks (`backupProblem` in `schema.ts`).
- **Repository:** reads the export rows and stamps `lastBackup`.
- **One native module, `src/lib/backup.ts`:** does the file, share and picker work with expo-file-system, expo-sharing, expo-document-picker and the expo-sqlite serialize/deserialize/backup functions.

**Tech Stack:** Expo SDK 58: expo-sqlite, expo-file-system (`File`, `Paths`), expo-sharing and expo-document-picker.

**Spec:** `docs/superpowers/specs/2026-11-11-backup-design.md`

## Global Constraints

- **Installing:** use `npx expo install expo-file-system expo-sharing expo-document-picker` only, with no other packages.
- **File names:** `workout-backup-YYYY-MM-DD.db` and `workouts-YYYY-MM-DD.csv`, with local dates (`localDateString`).
- **CSV columns:** `date,day,exercise,variation,set,type,reps,weight,unit,note`. Completed workouts only. Weight is in the current unit via `toDisplayWeight`, and empty for partial rows.
- **Exact copy:**
  - "This file isn't a backup from this app."
  - "This backup is from a newer version of the app. Update the app first."
  - "Replace everything on this phone with the backup from {date}? This includes any workout in progress and can't be undone."
- **Web:** no actions, just the note "Backup and export work in the phone app."
- **Don't commit, and never add co-author lines** (user CLAUDE.md).

## Review Focus

1. **A random file picked for restore** (an image, an empty file): deserializing throws, or the tables are missing. Either way it shows the "isn't a backup" message and changes nothing. A `backupProblem` test plus a try/catch around deserialize.
2. **A restore that fails midway:** `backupDatabaseAsync` is SQLite's own all-or-nothing copy, so on an error show "Could not restore. Nothing was changed." Not unit-testable here; covered by review.
3. **A name with a comma or a quote** ("Press, incline"): quoted correctly. A CSV test.
4. **A backup taken mid-workout, then restored:** the workout comes back in progress, and auto-end applies as usual.
5. **Backing up twice on the same day:** the same file name in the cache is overwritten, not an error (delete the file if it exists, then create it).

### Task 2: The native module, the More card and the docs

**Files:**
- Create: `src/lib/backup.ts`.
- Modify: `src/app/(tabs)/more/index.tsx`, `src/theme/settings.tsx` (add `reloadSettings(): Promise<void>` to the context), `package.json` (via `npx expo install`), `SPEC.md` (3.10 More and 6 Storage), and PRD 4.5 marked "BUILT".

**Produces (`backup.ts`, native only):**
- `backUp(db): Promise<void>`:
  1. `saveSetting(db, 'lastBackup', new Date().toISOString())`;
  2. `bytes = await db.serializeAsync()`;
  3. write `new File(Paths.cache, name)`, deleting it first if it exists;
  4. `Sharing.shareAsync(file.uri, { mimeType: 'application/octet-stream', dialogTitle: 'Save backup' })`.
- `exportCsv(db, unit): Promise<void>`: `toCsv(await getExportRows(db, unit))` goes to a `.csv` in the cache, then `shareAsync` with `mimeType: 'text/csv'`.
- `pickBackup(): Promise<{ memDb: SQLiteDatabase; backupDate: string | null } | { problem: string } | null>`:
  - `getDocumentAsync({ copyToCacheDirectory: true })`, and null when cancelled;
  - read the bytes with `new File(uri).bytes()`;
  - `deserializeDatabaseAsync(bytes)`, where a throw means the not-a-backup problem;
  - read `PRAGMA user_version` and the `sqlite_master` table names, then `backupProblem`;
  - `backupDate` comes from the memory database's `settings` `lastBackup`, read safely, since the table may be missing.
- `restoreFrom(memDb, db): Promise<void>`:
  1. `backupDatabaseAsync({ sourceDatabase: memDb, sourceDatabaseName: 'main', destDatabase: db, destDatabaseName: 'main' })`;
  2. `initializeDatabase(db)`, which runs the migrations;
  3. `memDb.closeAsync()`.

**The More card:**
- under the stats, "Last backup {formatDateLong}" or "No backup yet";
- the buttons "Back up" and "Export CSV" side by side;
- a link-style "Restore from backup";
- each action has a busy guard, and its errors show the spec's message inline.

**On restore:**
1. `pickBackup`; a problem gets an inline message;
2. `confirmAsync(..., 'Restore', true)`;
3. `restoreFrom`;
4. `reloadSettings()`;
5. `rest.cancelFor` for any running rest, which is simplest as a new `cancelAll()` in `restTimer.tsx`, or call `skip` and `dismiss`;
6. `router.replace('/workouts')`.
